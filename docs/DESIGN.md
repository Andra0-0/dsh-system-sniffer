# 设计

一页面板 + 一个工具，共用一套采集层。这份文档只解释**为什么这样分层**，行为细节见
`DETAIL.md`，踩过的坑见 `PITFALLS.md`。

## 三条不变式

1. **采样归 Host，不归页面。** 页面会被布局卸载（切页签、切面板、换会话），把定时器放在页面
   里就会出现一段空洞，回来时曲线是断的。Host 记住最近 60 秒，页面只负责把窗口画出来。
2. **面板关掉就不再付钱。** 除了预热的那几段，没人看的段不该有采样成本：`processes` 与
   `volumes` 各有一份 30 秒租约，到期停采；追踪的预览 5 秒没人看就丢。
3. **数据与结论分开。** 工具只返回数值和「这个段为什么没数」，不下判断。模型能自己看图，但
   追溯不了被插件加工过的结论。

## 段模型

`sections.js` 是唯一的表：每个段声明自己的采样间隔、历史深度、寿命、由哪个采集器喂、怎么把
一行原始数据抽成值。面板的页签只是段的命名分组，工具的 `include` 枚举也从这张表派生，所以
新增一个数据源是加一行，不是改一条链路。

历史是选配：`historyMs: 0` 只留最新值（表格、卡片），只有要画线的段才带窗口。

## 采样与租约

Host 按段自己的节拍写 `Store`：标量进 60 秒环形窗口，当前值对象另存。一次读取只是把已经在
内存里的东西拷一份，唤醒成本为零。

谁来采由**租约**决定：面板每次请求带 `client` 与 `include`，Host 按 client 记账；没有租约的
段进入寿命倒计时（`lifeMs`），到期停采并把状态置 `idle`。`Infinity` 的段一旦唤醒就常驻——
预热就是这条规则的产物：`warm` 为真时激活即唤醒 cpu / memory / network / gpu / diskio，代价
是一个常驻子进程（约 23 MB），换来打开面板首帧就有数。

客户端离开时先停轮询、再发一次空 `include` 主动释放；浏览器被杀掉的残余租约由 120 秒 TTL
兜底。

## 两个采集源

| 源 | 负责 | 代价 |
|---|---|---|
| 原生子进程（koffi → `pdh.dll` / `ntdll.dll`） | 进程表、三组 PDH 计数器、图标、FileDescription | 一个子进程，约 23 MB 私有内存 |
| `typeperf` 子进程 | 回退：每组一个 | 每组约 1.4 s 启动，最小采样间隔 1 s |

原生优先，因为 PDH 的 `\Process(*)` 实例表在查询打开时就冻结了，用它做进程列表等于拿
Host 启动那一刻的名单。原生路径还顺手解决了系统语言（`PdhAddEnglishCounterW`）与首帧慢的
问题。

降级是**逐组**的，不是全有全无：某台机器没有 GPU 计数器，只该把 `gpu` 交给 typeperf，
`core` 与 `disk` 仍走原生。因此 `pdh-status` 按组报可用性，`fallenBack` 按段记录，一个 watchdog
兜住「计数器加上了、行永远不来」这种静默情况。

回退是**粘性**的：两个来源的时间基准不同，来回切换会让曲线在两个时钟之间跳。

## 时间基准

所有时间戳都是真实时刻（wall clock），不是「第 N 拍」。速率计数器的首拍 PDH 自己会报
`INVALID_DATA`，那些点进窗口前就丢掉；原生子进程重启后的一两拍 `null` 会保留成缺口，而不是
复制上一个点——缺口是真的，连起来就是假数据。

## 追踪

追踪不是段，是一个环：Host 用虚拟 client `trace` 持一份 `processes` 租约，每秒从进程快照里挑
目标成员，写 6 条列式环（8 小时，约 1.4 MB，不落盘）。

- **预览**只在有人看时采：请求续一次查看者 TTL，最后一个窗口离开 5 秒就丢环、放租约。
- **录制**才无条件继续，只有用户点停止或清空才结束。
- 读数据两条路：实时走游标只补新点，缩放 / 平移走 `/trace/range`。range 按「窗口里的点装不装
  得下」分形态：装得下（1 Hz 下 20 分钟以内）直接回原始采样 + 真实 `times`；更宽才在全分辨率上
  按 min/max 桶化，桶宽不小于 2 个采样间隔，返回 ≤1200 点。两种形态在页面上是同一条渲染路径
  （有 `times` 就按真实时间摆点），所以同一个环不会因为窗口挪了个位置就从连续变成碎裂。

## 磁盘扫描

扫描是 job，不是段：一次一个，可取消，状态在跑的过程中发布。它只读目录名与大小，不读文件
内容；对模型可见的级数由 `diskTool` 决定（`off` / `numbers` / `names`），默认关闭。

## 边界

- **Windows only**：PDH、`NtQuerySystemInformation`、`SHGetFileInfo` 都是 Win32。
- **x64 布局**：`SYSTEM_PROCESS_INFORMATION` 的偏移按 x64 写死。
- **回退路径的差异**：typeperf 兜底时进程项没有 `appId`，追踪的组目标会采不到点；数字口径
  与原生一致，但首帧慢、采样率下限 1 s。
- **不回答「为什么卡」**：只交数据，结论由模型或人下。
